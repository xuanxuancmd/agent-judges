# TODO 列表应用：需求规格说明

## 1. 背景与目标

日常任务一多，脑子就记不过来。用户需要一个轻量、零依赖的工具，把待办事项写下来、跟踪完成进度，并按截止日期看到哪些事该先做。本应用面向个人用户，强调快速录入和离线可用，不依赖任何服务端。

目标：交付一个在浏览器里直接打开就能用的 TODO 列表应用，覆盖任务的创建、编辑、删除、完成切换与列表筛选，数据保存在本地。

## 2. 用户故事

1. 作为一名用户，我希望能新增一条待办事项，写明标题和可选的截止日期，这样我就不会忘。
2. 作为一名用户，我希望能修改已有事项的标题或截止日期，计划变了能跟着改。
3. 作为一名用户，我希望能把事项标记成完成，也能把误标完成的重新打开，这样进度才准。
4. 作为一名用户，我希望能按"全部 / 未完成 / 已完成"切换视图，只看我现在关心的事。
5. 作为一名用户，我希望关掉浏览器再打开，列表还在，不用重新输一遍。

## 3. 功能需求

### 3.1 事项字段

每条事项至少包含以下字段：

- 唯一 ID
- 标题（必填，非空）
- 截止日期（可选，格式 YYYY-MM-DD）
- 完成状态（布尔）
- 创建时间

### 3.2 增删改查

- 新增：输入标题与可选截止日期后创建一条事项。
- 编辑：可修改标题与截止日期。
- 删除：可移除指定事项。
- 查询：列表展示当前全部事项。

### 3.3 完成与取消

- 未完成事项可标记为完成。
- 已完成事项可重新标记为未完成。

### 3.4 列表筛选

提供三种视图：全部、未完成、已完成。默认进入时显示未完成。

### 3.5 截止日期

- 截止日期为可选字段，格式 YYYY-MM-DD。
- 当事项已过期且未完成时，在列表中以视觉方式提示用户。

### 3.6 本地持久化

- 数据保存在浏览器 localStorage 中。
- 页面加载时自动读取并恢复列表。

## 4. 非功能需求

- 性能：界面响应应尽量快，列表的增删改操作无明显卡顿。
- 兼容性：支持主流现代浏览器，包括 Chrome、Edge、Firefox 的最近两个大版本。
- 可维护性：代码结构清晰，核心逻辑与界面渲染分离，便于后续调整。

## 5. 验收标准

1. 用户能新增、编辑、删除事项，操作完成后列表立即反映最新状态。
2. 关闭并重新打开页面后，之前的数据仍然保留。
3. 在全部、未完成、已完成三种视图间切换，展示的列表与筛选条件一致。
4. 过期且未完成的事项在列表中有明显的视觉标识。
5. 界面应美观易用，布局合理，操作顺手。

## 6. 范围与非目标

范围：

- 单用户、单设备的本地 TODO 列表。

非目标：

- 不提供账号系统，不做多端同步。
- 不提供通知或推送提醒。
- 不支持子任务、嵌套结构。
- 不支持标签或分类。
