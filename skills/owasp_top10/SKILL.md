# OWASP Top 10 (2021) 审查指引

## 审查方法

1. 先通读被审查内容，标记所有涉及以下类别的部分:
   认证/授权、数据存储与传输、输入处理、外部依赖、配置、日志
2. 对每个类别，逐条对照下方风险定义检查
3. 每条 finding 必须引用被审查内容中的具体证据（原文位置/片段）

## 风险定义速查

| # | 风险 | 典型信号 |
|---|---|---|
| A01 | 失效的访问控制 | 直接对象引用、缺少服务端权限校验、CORS 全开 |
| A02 | 加密机制失效 | 明文存储密码、HTTP 传输敏感数据、弱哈希(MD5/SHA1) |
| A03 | 注入 | 字符串拼接 SQL/命令、eval 用户输入、不安全的 ORM 用法 |
| A04 | 不安全设计 | 业务流程缺信任边界、单点校验、无速率限制的敏感操作 |
| A05 | 安全配置错误 | 默认凭证、debug=true 上线、目录列举、过详细错误信息 |
| A06 | 易受攻击的组件 | 固定旧版本依赖、未锁定的依赖范围 |
| A07 | 认证失效 | 弱密码策略、无 MFA 的高权限入口、会话不过期 |
| A08 | 完整性故障 | 反序列化不可信数据、无签名的自动更新 |
| A09 | 日志监控失效 | 登录失败无日志、审计日志可被用户删除 |
| A10 | SSRF | 用户可控的 URL 回调、无白名单的内部请求 |

## 定级基准

- critical: 可直接导致数据泄露或远程执行
- major: 可被利用但需要特定条件
- minor: 纵深防御缺失（defense-in-depth gap）
