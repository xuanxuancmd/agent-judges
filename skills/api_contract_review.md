# API 契约完整性审查指引

审查任何 API 定义（OpenAPI/Proto/接口文档）时，逐项检查:

## 1. 契约要素完备性

每个接口必须定义:

- 输入: 参数名、类型、必填性、取值范围、默认值
- 输出: 成功响应结构 + **错误响应结构**（错误码 + 语义）
- 副作用: 是否幂等、是否有副作用说明
- 权限: 调用者需要的角色/权限

## 2. 错误路径覆盖

- 每个接口至少定义: 400（参数错误）、401/403（认证/授权）、429（限流）、5xx（内部错误）
- 错误码有唯一语义，不与其他接口冲突
- 错误信息不泄露内部实现（堆栈、SQL、内部路径）

## 3. 边界条件显式化

- 分页: 上限、默认值、越界行为
- 大请求体: 大小上限与超出行为
- 并发: 并发修改的语义（乐观锁/版本号/覆盖）

## 4. 版本与兼容

- 破坏性变更有版本策略（URL/头/MediaType）
- 废弃接口有 sunset 说明

## 输出要求

缺失项逐条列为 finding；evidence 引用契约原文位置；对"文档有描述但不可验证"的项降低 confidence。
